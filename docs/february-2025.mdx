## In this release

Scrut’s February 2025 release adds two new compliance frameworks, introduces internal and external audits, gives users more granular control when adding frameworks to the Trust Portal, and trims manual work from vendor onboarding and export workflows.

- SEBI CSCRF and NIST 800-53 (High Baseline) join Scrut's framework library, with pre-mapped controls for financial market entities and high-impact systems working toward compliance.
- Schedule internal and external audits separately for each framework, with a full calendar view for planning across current, past, and upcoming years.
- Ask clarifying questions directly on vendor intake form responses, with inline replies and attachments, instead of switching to email or chat.
- Assign multiple owners to vendors, questionnaires, and mitigation tasks so work no longer bottlenecks behind a single person.
- Export policies, evidence, and controls in bulk with checkbox selection, without pulling an entire framework's worth of data.

## Key Features & Enhancements

### Adopt SEBI CSCRF with pre-mapped controls

Financial market entities regulated by SEBI must comply with the Cyber Security and Cyber Resilience Framework (CSCRF), covering incident reporting, risk assessments, and governance controls. Without a mapped framework in your GRC tool, security and compliance teams build this mapping manually. That slows down audits and increases the risk of penalties for non-compliance.

SEBI CSCRF is now available in the Frameworks module in Scrut, with controls pre-mapped to help you align with its requirements.

  Learn more: [SEBI CSCRF](/docs/framework-overview#sebi-cscrf-securities-and-exchange-board-of-india-cyber-security--cyber-resilience)

### Manage NIST 800-53 High Baseline compliance in Scrut

Organizations handling highly sensitive data, such as government agencies, critical infrastructure operators, and financial institutions, must meet the stringent security requirements of the NIST 800-53 High Baseline. Without built-in framework support, compliance teams map these advanced controls manually.

Scrut now supports NIST 800-53 (High Baseline) in the Frameworks module, with controls pre-mapped to your existing evidence. This strengthens access controls, encryption, and monitoring for mission-critical systems. It also streamlines documentation and evidence collection, making it easier to demonstrate compliance during audits.

<Callout kind="info">
  Learn more: [NIST 800-53 High Baseline](/docs/framework-overview#nist-800-53-rev5-high-baseline)
</Callout>

### Select the frameworks to display in your Trust Portal

Prospects and customers increasingly expect a trust portal to reflect the frameworks a vendor actually operates, not a static marketing list. The Trust Vault module now lets admins search, add, edit, hide, or delete the compliance frameworks shown to visitors, including custom logos for branding.

### Schedule both internal and external audits for each framework

Audit scheduling in Scrut only supported one audit date per framework, which didn't work for teams juggling separate internal and external audits. There was no way to distinguish an internal audit from an external one.

You can now create multiple audits per framework and classify each as internal or external. Only one active external audit is allowed per framework at a time. A full calendar view lets you see audit schedules across the current, previous, and upcoming years.

### Ask clarifying questions directly on vendor intake forms

Reviewing a vendor onboarding request usually involves either approving or rejecting it outright, with no way to ask a follow-up question on a specific response. Getting clarification meant asking follow-up questions via email or chat. This back-and-forth slows down onboarding and makes it easy to lose track of what was asked and answered.

Scrut now allows admins and reviewers to comment directly on specific intake form questions to request clarification, and employees are notified and can reply inline. Both admins and employees can attach supporting documents to the form as the conversation continues.

### Track and manage Trust Portal access reclaims

When a user with expired Trust Portal access requests it again, admins have no way to tell a reclaim request apart from a brand new one. Both new and reclaim requests land in the same queue, so admins cannot prioritize or filter by request type.

Scrut now tags each portal access request as New or Reclaim, and expired-access users move automatically into the Pending tab when they request access again. When you approve a reclaim, Scrut shows the previous expiration date, NDA configuration, and document access configuration, so you only need to set the new expiry duration.

### Assign multiple owners across vendor workflows

Large vendor programs choke on a bottleneck when only one person can own a vendor record, questionnaire review, or mitigation task. Work queues serialize behind a single assignee, and coverage drops when that person is out.

Scrut's Vendor module now supports multiple assignees and reviewers for vendors, questionnaires, and mitigation tasks. Workload and visibility stay inside the vendor workflow instead of informal side ownership.

## Other Updates

- [ISO 42001](/docs/framework-overview#iso-420012023) and [Digital Operational Resilience Act (DORA)](/docs/framework-overview#dora) mappings were updated by adding or removing controls, evidence, and policies to improve usability while preserving coverage.
- Evidence attachments are organized based on the [fiscal year set in Settings → Organization Info](/docs/set-fiscal-year-format).
- You can now [set a specific launch and end time for every training campaign](/docs/create-security-awareness-campaign), and choose the time zone based on where your employees are located.
- [Automatically create a Jira ticket](/docs/creating-jira-ticket) when an evidence task moves to Needs Attention status.
- Scrut now [integrates with Trello](/docs/integrating-trello). You can create Trello tasks directly from Scrut, link existing tasks, and monitor task status in real-time.
- Scrut now supports [PingOne integration](/docs/integrating-pingidentity) by PingIdentity. This is an SSO-only integration and will enable employees of an organization to log in to Scrut using PingOne SSO.
- Approved [Trust Portal](/docs/trust-vault-user-navigation) users can log out on demand, ending sessions across devices and requiring one-time password (OTP) authentication to return, with private documents inaccessible after logout.
- Source Type is automatically assigned when [risks are added manually or via bulk import](/docs/adding-a-new-risk).
- [Access Review](/docs/creating-a-new-access-review) now has a two-person workflow, ensuring that every application under review has both a dedicated Reviewer and an Approver.
