---
title: How to Check Plugin Conflicts in WordPress
description: >-
  Identify and resolve WordPress plugin conflicts using the Health Check &
  Troubleshooting plugin or manual activation/deactivation testing.
type: guide
---
A WordPress plugin is a software component that adds specific features or functionality to a WordPress website without requiring any coding. Plugins are essential to the WordPress ecosystem, letting you customize your site easily. However, when two or more plugins perform the same task or compete for the same resources, they can conflict — leading to errors or performance problems.

Plugin conflicts can be frustrating to track down, but a few simple guidelines make them much easier to identify and resolve.

<Tabs>
  <Tab title="Tab 1">
    We recommend using the **Health Check & Troubleshooting** plugin to identify conflicts on a live WordPress site, rather than deactivating plugins individually. It diagnoses and troubleshoots problems without disrupting your site's normal functionality for visitors.

    <Steps>
      <Step title="Install the Health Check & Troubleshooting plugin" title-type="p">
        Go to **Dashboard → Plugins → Add New**, then search for, install, and activate the [Health Check & Troubleshooting](https://wordpress.org/plugins/health-check/) plugin.
      </Step>

      <Step title="Open Site Health" title-type="p">
        Go to **Admin Panel → Tools → Site Health** and select the **Troubleshooting** tab.
      </Step>

      <Step title="Enable Troubleshooting Mode" title-type="p">
        Turn on **Troubleshooting Mode**. This deactivates every plugin except Health Check & Troubleshooting itself.
      </Step>

      <Step title="Re-enable plugins one at a time" title-type="p">
        Turn plugins back on individually, checking for the issue after each one using an incognito or private browsing window.
      </Step>

      <Step title="Identify and disable the conflicting plugin" title-type="p">
        Once you find the plugin causing the conflict, disable it, then exit Troubleshooting Mode to restore your site's normal functionality.
      </Step>

      <Step title="Report the conflict" title-type="p">
        Report the plugin conflict to the respective plugin's author or support team for further assistance.
      </Step>
    </Steps>

    <Callout kind="info" collapsed="false">
      Site visitors continue to see your site normally while it's in Troubleshooting Mode — only you, as the logged-in admin running the test, see the deactivated plugins.
    </Callout>
  </Tab>

  <Tab title="Tab 1">
    If you'd rather not use a third-party plugin to test for conflicts, you can manually activate and deactivate plugins to isolate the source of the issue.

    <Steps>
      <Step title="Open your plugins list" title-type="p">
        Go to **Plugins** in your WordPress Admin Panel to see all installed plugins.
      </Step>

      <Step title="Deactivate plugins one at a time" title-type="p">
        Deactivate each plugin individually, checking your website for the problem after every deactivation.
      </Step>

      <Step title="Report the conflicting plugin" title-type="p">
        Once you've identified the plugin causing the conflict, report the issue to its author or support team. Keep the plugin disabled until the developers resolve the issue.
      </Step>
    </Steps>

    <Callout kind="alert" collapsed="false">
      Create a full website backup before running a plugin conflict test on a live or production site. Alternatively, perform the test on a local or staging copy of your website.
    </Callout>
  </Tab>
</Tabs>
