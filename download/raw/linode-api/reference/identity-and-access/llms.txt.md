## API Reference: Identity and access
- [List entities](https://techdocs.akamai.com/linode-api/reference/get-entities.md): Lists entities created on the account. An *entity* is an object that has a life-cycle and can be managed by an authorized user within an account, for example: a specific virtual machine or firewall. You can manage an entity over time by performing operations on it, based on your access level.  > 📘 Before you begin > > Before you run this operation, read [Comparison of Linode API for grants and Identity and Access](https://techdocs.akamai.com/cloud-computing/docs/migration-grants-identity-and-access#comparison-of-linode-api-for-grants-and-identity-and-access) to learn about the new experience and recommended use of the Identity and Access endpoints.   **Permissions and scopes**  To call this operation, you need the following:  - **Identity and access permissions**. Your user needs a role with these permissions assigned. [Learn more](https://techdocs.akamai.com/cloud-computing/docs/identity-access-cm-available-roles).   - Permissions: `list_entities`
- [List available roles](https://techdocs.akamai.com/linode-api/reference/get-role-permissions.md): Lists available account access and entity access roles, their descriptions, and included permissions. Use these roles to manage users' access level to specific services and entities.  - **Account access roles**. These roles give access to account level operations, entities in the account both existing and to be created in the future, and creation of new entities.  - **Entity access roles**. These roles provide access to specific entities that are already available on the account.  To learn more, see the [Identity and Access in Cloud Manager terminology](https://techdocs.akamai.com/cloud-computing/docs/identity-and-access-cm#terminology).  > 📘 Before you begin > > Before you run this operation, read [Comparison of Linode API for grants and Identity and Access](https://techdocs.akamai.com/cloud-computing/docs/migration-grants-identity-and-access#comparison-of-linode-api-for-grants-and-identity-and-access) to learn about the new experience and recommended use of the Identity and Access endpoints.   **Permissions and scopes**  To call this operation, you need the following:  - **Identity and access permissions**. Your user needs a role with these permissions assigned. [Learn more](https://techdocs.akamai.com/cloud-computing/docs/identity-access-cm-available-roles).   - Permissions: `list_role_permissions`
- [Get a user's access level](https://techdocs.akamai.com/linode-api/reference/get-iam-users-role-permissions.md): Returns a user's access level on the account. The response includes account access and entity access roles.  - **Account access roles**. These roles give access to account level operations, entities in the account both existing and to be created in the future, and creation of new entities.  - **Entity access roles**. These roles provide access to specific entities that are already available on the account.  To learn more, see the [Identity and Access in Cloud Manager terminology](https://techdocs.akamai.com/cloud-computing/docs/identity-and-access-cm#terminology).  > 📘 Before you begin > > Before you run this operation, read [Comparison of Linode API for grants and Identity and Access](https://techdocs.akamai.com/cloud-computing/docs/migration-grants-identity-and-access#comparison-of-linode-api-for-grants-and-identity-and-access) to learn about the new experience and recommended use of the new Identity and Access endpoints.   **Permissions and scopes**  To call this operation, you need the following:  - **Identity and access permissions**. Your user needs a role with these permissions assigned. [Learn more](https://techdocs.akamai.com/cloud-computing/docs/identity-access-cm-available-roles).   - Permissions: `list_user_permissions`
- [Update a user's access level](https://techdocs.akamai.com/linode-api/reference/put-iam-users-role-permissions.md): Updates a user's access level on the account. The request includes account access and entity access roles.  - **Account access roles**. These roles give access to account level operations, entities in the account both existing and to be created in the future, and creation of new entities.  - **Entity access roles**. These roles provide access to specific entities that are already available on the account.  To learn more, see the [Identity and Access in Cloud Manager terminology](https://techdocs.akamai.com/cloud-computing/docs/identity-and-access-cm#terminology). This operation replaces any existing role assignment. To completely block user's access to the account, pass an empty list, `[]`. To get the list of available roles, run the [List available roles](ref:get-role-permissions) operation.  > 📘 Before you begin > > Before you run this operation, read [Comparison of Linode API for grants and Identity and Access](https://techdocs.akamai.com/cloud-computing/docs/migration-grants-identity-and-access#comparison-of-linode-api-for-grants-and-identity-and-access) to learn about the new experience and recommended use of the new Identity and Access endpoints.   **Permissions and scopes**  To call this operation, you need the following:  - **Identity and access permissions**. Your user needs a role with these permissions assigned. [Learn more](https://techdocs.akamai.com/cloud-computing/docs/identity-access-cm-available-roles).   - Permissions: `update_user_permissions`
- [Create an IDP configuration](https://techdocs.akamai.com/linode-api/reference/post-idp-config.md): __Beta__ Creates an external identity provider (IDP) configuration for the account. You can have only one configuration per account. To learn more about the single sign-on for Akamai Cloud, including emergency access accounts setup, see [Single Sign-On](https://techdocs.akamai.com/cloud-computing/docs/single-sign-on-cm).  **Prerequisite**  You need to have IDP metadata from your identity provider.  To create the IDP configuration:  1. Provide a unique label for the configuration. 1. To activate the SSO, set `enabled` to `true`. 1. Enforce SSO for all users of your account with `enforce` set to `true`. The enforcement doesn't apply to users listed as [SSO user exceptions](ref:get-idp-config-users-excluded).      > 📘     >     > Set the enforcement to `false`, if you want to test SSO on a small subset of users. After you create this configuration, [add the SSO-required users](ref:put-idp-config-users-included) and test the login flow. If the test is successful, enforce the SSO login for all users with the [Update an IDP configuration](ref:put-idp-config) operation.  1. Specify the SAML configuration settings with details from the IDP metadata you got from the identity provider.  > 👍 There's a tutorial > > We offer an example API [workflow](ref:configure-sso-login) you can follow to create an IDP configuration, test it, and configure an account with emergency access.  > 📘 > > This operation is in Beta and available from the `v4beta` URL.   **Permissions and scopes**  To call this operation, you need the following:  - **Identity and access permissions**. Your user needs a role with these permissions assigned. [Learn more](https://techdocs.akamai.com/cloud-computing/docs/identity-access-cm-available-roles).   - Permissions: `create_idp_config`
- [List IDP configurations](https://techdocs.akamai.com/linode-api/reference/get-idp-configs.md): __Beta__ Returns a list of all external identity provider (IDP) configurations for the account. For the initial release, the list contains only a single item.  > 📘 > > This operation is in Beta and available from the `v4beta` URL.   **Permissions and scopes**  To call this operation, you need the following:  - **Identity and access permissions**. Your user needs a role with these permissions assigned. [Learn more](https://techdocs.akamai.com/cloud-computing/docs/identity-access-cm-available-roles).   - Permissions: `view_idp_config`
- [Get an IDP configuration](https://techdocs.akamai.com/linode-api/reference/get-idp-config.md): __Beta__ Returns the external identity provider (IDP) configuration for the account.  > 📘 > > This operation is in Beta and available from the `v4beta` URL.   **Permissions and scopes**  To call this operation, you need the following:  - **Identity and access permissions**. Your user needs a role with these permissions assigned. [Learn more](https://techdocs.akamai.com/cloud-computing/docs/identity-access-cm-available-roles).   - Permissions: `view_idp_config`
- [Update an IDP configuration](https://techdocs.akamai.com/linode-api/reference/put-idp-config.md): __Beta__ Updates the external identity provider (IDP) configuration for the account. Top-level properties can be passed individually or together.  When included, you need to provide the entire IDP config object and it will overwrite existing values. This operation triggers an `update_idp_config` event.  > 📘 > > This operation is in Beta and available from the `v4beta` URL.   **Permissions and scopes**  To call this operation, you need the following:  - **Identity and access permissions**. Your user needs a role with these permissions assigned. [Learn more](https://techdocs.akamai.com/cloud-computing/docs/identity-access-cm-available-roles).   - Permissions: `update_idp_config`
- [Delete an IDP configuration](https://techdocs.akamai.com/linode-api/reference/delete-idp-config.md): __Beta__ Deletes the external identity provider (IDP) configuration for the account. The configuration object is soft-deleted, while certificates and user lists for both SSO-required or SSO exceptions are permanently deleted.  > 📘 > > This operation is in Beta and available from the `v4beta` URL.   **Permissions and scopes**  To call this operation, you need the following:  - **Identity and access permissions**. Your user needs a role with these permissions assigned. [Learn more](https://techdocs.akamai.com/cloud-computing/docs/identity-access-cm-available-roles).   - Permissions: `delete_idp_config`
- [Add an IDP certificate](https://techdocs.akamai.com/linode-api/reference/post-idp-config-certificate.md): Adds a new public certificate to the external identity provider (IDP) configuration. One configuration can have several certificates to support a certificate rotation.   **Permissions and scopes**  To call this operation, you need the following:  - **Identity and access permissions**. Your user needs a role with these permissions assigned. [Learn more](https://techdocs.akamai.com/cloud-computing/docs/identity-access-cm-available-roles).   - Permissions: `create_idp_config_cert`
- [List IDP certificates](https://techdocs.akamai.com/linode-api/reference/get-idp-config-certificates.md): Returns the list of public certificates for the external identity provider (IDP) configuration. The IDP configuration needs to have at least one valid certificate at all times. You can [add several certificates](ref:post-idp-config-certificate) or [remove the expired ones](ref:delete-idp-config-certificate).   **Permissions and scopes**  To call this operation, you need the following:  - **Identity and access permissions**. - [Delete an IDP certificate](https://techdocs.akamai.com/linode-api/reference/delete-idp-config-certificate.md): Deletes a specific certificate from the external identity provider (IDP) configuration. The IDP configuration needs to have at least one valid certificate at all times. If all existing certificates are expired, [add a new valid one](ref:post-idp-config-certificate) before removing the expired ones.   **Permissions and scopes**  To call this operation, you need the following:  - **Identity and access permissions**.
