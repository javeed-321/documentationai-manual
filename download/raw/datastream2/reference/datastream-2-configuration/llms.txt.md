# DataStream 2 Documentation

> Akamai's DataStream provides real-time access to application activity data, including aggregated metrics on complete request-response cycles as well as origin response times. It helps simplify web application monitoring, and includes applications deployed to cloud hosting providers and applications that leverage third-party services.

Fetch the complete documentation index at: https://techdocs.akamai.com/datastream2/llms.txt. Use this file to discover all available pages before exploring further. Append .md to any documentation page URL to get its markdown version.

## API Reference: DataStream 2 configuration
- [List AnswerX service instances by contract](https://techdocs.akamai.com/datastream2/reference/get-answerx-ssids.md): Returns the AnswerX Recursive DNS Service IDs (SSIDs) on your contract. Run this operation to get the `ssid` values you need to [Create an AnswerX stream](ref:post-stream-answerx) or [Edit an AnswerX stream](ref:put-stream-answerx).
- [Create an AnswerX stream](https://techdocs.akamai.com/datastream2/reference/post-stream-answerx.md): Creates a stream configuration that delivers AnswerX Recursive DNS logs. You can choose the service instances (SSIDs) to monitor in the stream, data set fields to collect in logs, and a destination to send these log files to. Get the `ssid` values from [List AnswerX service instances](ref:get-answerx-ssids). Apart from the log and delivery frequency configurations, you can decide to `activate` the stream when making the request, or later. Note that only active streams collect and send logs to their destinations. See [Activate a stream](ref:post-stream-activate).
- [Edit an AnswerX stream](https://techdocs.akamai.com/datastream2/reference/put-stream-answerx.md): Updates the latest version of an AnswerX stream. Each time you edit a stream, its version number increments. Note that only active streams collect and send logs to their destinations. You need to set the `activate` parameter to `true` while editing active streams, and optionally for inactive streams if you want to activate them upon request. See [Version management](ref:version-management) and [Activate a stream](ref:post-stream-activate).
- [List Application Security configurations](https://techdocs.akamai.com/datastream2/reference/get-configs-appsec.md): Returns all Application Security configurations on your contract. Run this operation to get the `id` and `name` values you need as `appSecId` and `appSecName` to run [Create a security log stream](ref:post-stream-appsec) or [Edit a security log stream](ref:put-stream-appsec). Run [List groups](ref:get-groups) to get the `groupId` and `contractId`.
- [Create a security log stream](https://techdocs.akamai.com/datastream2/reference/post-stream-appsec.md): Creates a stream configuration for [Security Information and Event Management](https://techdocs.akamai.com/datastream2/reference/security-logs) (SIEM) events. Logging security events requires enabling data collection for [SIEM integrations](https://techdocs.akamai.com/siem-integration/docs/akamai-siem-integration-for-splunk-and-cef-syslog#step-1-turn-on-siem-integration) in your security configuration. For details on this log type, see [Security logs](ref:log-types#security-logs).  Run [List security configurations](ref:get-configs-appsec) to get the security configuration `id` and `name` you can use as the `appSecId` and `appSecName`.  You can `activate` the stream when making the request, or later. Note that only active streams collect and send logs to their destinations. See [Activate a stream](ref:post-stream-activate).
- [Edit a security log stream](https://techdocs.akamai.com/datastream2/reference/put-stream-appsec.md): Updates the latest version of a [Security Information and Event Management](https://techdocs.akamai.com/datastream2/reference/security-logs) (SIEM) events stream for Application Security. Each time you edit a stream, its version number increments. Note that only active streams collect and send logs to their destinations. You need to set the `activate` parameter to `true` while patching active streams, and optionally for inactive streams if you want to activate them upon request. See [Version management](ref:version-management) and [Activate a stream](ref:post-stream-activate).
- [Patch a security log stream](https://techdocs.akamai.com/datastream2/reference/patch-stream-appsec.md): Updates selected details of an existing [Security Information and Event Management](https://techdocs.akamai.com/datastream2/reference/security-logs) (SIEM) events stream. Running this operation using [JSON Patch](http://jsonpatch.com) syntax creates a stream version that replaces the current one. Currently you can patch a stream using only the `replace` operation. When updating configuration objects such as `destination` or `deliveryConfiguration`, pass a complete object to avoid overwriting current details with default values for omitted fields such as `tags`, `uploadFilePrefix`, and `uploadFileSuffix`. Note that only active streams collect and send logs to their destinations. You need to set the `activate` parameter to `true` while patching active streams, and optionally for inactive streams if you want to activate them upon request. See [Patching streams](ref:patching-streams) for details.
- [Delete a security log stream](https://techdocs.akamai.com/datastream2/reference/delete-stream-appsec.md): Deletes a deactivated [Security Information and Event Management](https://techdocs.akamai.com/datastream2/reference/security-logs) (SIEM) events stream. Deleting a stream means you can't activate this stream again, and you stop receiving logs for the properties this stream monitors. Before deleting any stream, you need to deactivate it first. See [Deactivate a stream](ref:post-stream-activate).
- [List security logs streams](https://techdocs.akamai.com/datastream2/reference/get-streams-appsec.md): Returns the [Security Information and Event Management](https://techdocs.akamai.com/datastream2/reference/security-logs) (SIEM) stream configurations' latest versions for all groups on your account. Use the `groupId` query parameter to view the latest versions of all configurations in a specific group, or up to five property names as the `objectName` parameter to get streams for specific properties.
- [List CDN properties by group](https://techdocs.akamai.com/datastream2/reference/get-properties-cdn.md): Returns delivery properties (also referred to as _objects_) active on the production and staging network within a specific group. Run this operation to get the `objectId` values you need to provide as `propertyId` to [Create a delivery stream](ref:post-stream-cdn) or [Edit a delivery stream](ref:put-stream-cdn).
- [List Edge DNS zones by contract](https://techdocs.akamai.com/datastream2/reference/get-properties-edns.md): Returns Edge DNS zones on your contract. Run this operation to get the `zoneName` values you need to [Create an Edge DNS stream](ref:post-stream-edns) or [Edit an Edge DNS stream](ref:put-stream-edns).
- [List GTM properties by contract](https://techdocs.akamai.com/datastream2/reference/get-properties-gtm.md): Returns Global Traffic Management (GTM) domain properties on your contract. Run this operation to get the `propertyName` values you need to [Create a GTM stream](ref:post-stream-gtm) or [Edit a GTM stream](ref:put-stream-gtm).

Running this operation using [JSON Patch](http://jsonpatch.com) syntax creates a stream version that replaces the current one. Currently you can patch a stream using only the `REPLACE` operation. When updating configuration objects such as `destination` or `deliveryConfiguration`, pass a complete object to avoid overwriting current details with default values for omitted fields such as `tags`, `uploadFilePrefix`, and `uploadFileSuffix`. - [List streams](https://techdocs.akamai.com/datastream2/reference/get-streams.md): Returns the stream configurations' latest versions for all groups on your account within a specific `logType`. Use up to five property names as the `objectName` parameter to get streams for specific properties.
- [View upload metrics](https://techdocs.akamai.com/datastream2/reference/get-streams-metrics.md): Returns aggregated metrics for log file uploads, including success or failure upload counts, upload latency, and the volume of data uploaded in the stream. Set the `start` and `end` dates to get metrics from a specific time range, and `aggregationInterval` to group data by time intervals.
- [Get a stream](https://techdocs.akamai.com/datastream2/reference/get-stream.md): Returns details about any version of a stream, including the monitored properties or zones, logged data set fields, and log delivery destination. If you omit the `version` query parameter, this operation returns the stream's last version.
- [Delete a stream](https://techdocs.akamai.com/datastream2/reference/delete-stream.md): Deletes a deactivated stream. Deleting a stream means you can't activate this stream again, and you stop receiving logs for the properties this stream monitors. Before deleting any stream, you need to deactivate it first. See [Deactivate a stream](ref:post-stream-activate).
- [List data set fields](https://techdocs.akamai.com/datastream2/reference/get-dataset-fields.md): Lists available data set fields you can choose to monitor in your logs in a stream configuration. Use the `logType` and `productId` parameters to get data sets available for a specific log type or product. Requests without `productId` return data set fields available for all products, omitting product-specific fields. Run this operation to get the `datasetFieldId` and `datasetFieldName` values you need to create or edit a stream.
- [List groups](https://techdocs.akamai.com/datastream2/reference/get-groups.md): Returns access groups with contracts on your account. You can later use the `groupId` and `contractId` values to create and view streams or list properties by group. Set the `contractId` query parameter to get groups for a specific contract.
- [Activate a stream](https://techdocs.akamai.com/datastream2/reference/post-stream-activate.md): Activates the latest version of a stream. Activating a stream takes approximately an hour. Once a stream is active, and the [DataStream behavior](https://techdocs.akamai.com/property-mgr/docs/datastream-beh) is enabled in Property Manager, it replaces and deactivates the previous version, then starts collecting data and sending log files to a destination. If you want to stop receiving the logs, you can [Deactivate a stream](ref:post-stream-activate) at any time. Run [List streams](ref:get-streams) to check your stream's activation status.
- [View activation history](https://techdocs.akamai.com/datastream2/reference/get-stream-activation-history.md): Returns the details of activation status changes for all versions of a given stream within a specific `logType`.
- [Deactivate a stream](https://techdocs.akamai.com/datastream2/reference/post-stream-deactivate.md): Deactivates the latest version of a stream. Deactivating a stream means that you stop receiving logs for properties this stream monitors, and changes status to `DEACTIVATED` in approximately an hour. If you want to start receiving log files again, you can activate the stream at any time using the [Activate a stream](ref:post-stream-activate) operation.
- [View history](https://techdocs.akamai.com/datastream2/reference/get-stream-history.md): Returns details about all versions of a given stream. It helps you track changes between the stream's versions, including monitored properties, logged data set fields, and log delivery destinations. Optionally, set both the `startVersion` and `endVersion` parameters to get details on all stream versions for a given range. For example, setting `startVersion` to `1` and `endVersion` to `3` returns details on the stream's `1`, `2`, and `3` versions.
