## What this add-on does

Webhooks and API help your WP Travel Engine site share booking data with other tools.

A **webhook** is an automatic notification sent from one system to another when something happens. For example, when someone sends an enquiry for a trek or books a multi-day package, your site can send that information out right away.

A **REST API** is a way for one app to request information from another app using web addresses. This lets another tool ask your site for trips, bookings, customers, or payment details when needed.

It gives you two main ways to connect your tour business systems:

- **Real-time webhooks** - push data out to other tools
- **REST API** - pull data in when another app asks for it

<Callout kind="info" collapsed="false">

This add-on is useful if you want to connect your tour site to a CRM, accounting software, WhatsApp or SMS tools, reporting dashboards, or a customer app. It also helps if you work with a developer who is building custom tools for your business.

</Callout>

## Why this is useful for your tour business

You can use this add-on to cut down manual work and keep your booking information up to date across the tools you already use.

- **Send new bookings into tools like Pabbly, Zapier, or Make** so your team does not need to copy customer details by hand.
- **Automate WhatsApp, SMS, or email notifications** when someone books a day tour, pays for a private trip, or sends an enquiry.
- **Connect with CRM or accounting tools** so your sales and finance records stay current.
- **Build a customer portal or mobile app** where travelers can check their trips, payments, or booking history.
- **Keep data secure and up to date** with structured access that happens in real time or on request.

That gives you the big picture. Next, make sure you have everything ready before you start.

### For webhooks

- A valid external URL. A Pabbly webhook URL works.
- The URL must accept **POST** requests
- The URL must return **HTTP 200**

A **POST request** means your site sends data to another tool.

**HTTP 200** means the other tool answers back to say it received the data successfully.

### For the API

- At least one API Key and Secret generated
- Permissions set for the data you want to access, such as bookings or trips
- Postman is optional, but helpful for testing

## Key features

These are the main things the add-on gives you.

- **Real-time webhooks** - Send instant updates for 7 different events.
- **Secure REST API** - Give read-only access to bookings, trips, customers, and payments.
- **Automatic retries** - If a webhook fails, the system tries again up to 5 times.
- **Email alerts** - Get an email when a webhook keeps failing.
- **Rate limiting** - Protect your site from too many API requests at once.
- **Response caching** - Save API responses for 1 hour to improve speed.
- **Developer friendly** - Full documentation is available, and WP-CLI support is included.

If webhooks are new to you, start there first. They are the easiest way to understand how this add-on works.

## Understanding webhooks

Webhooks are automatic notifications.

When something important happens on your site, your site sends the details to another tool right away. That could be a new enquiry, a booking, or a payment.

Here is a simple example. You run a travel agency and use Slack to keep your team updated. You can send booking details to your Slack webhook URL, and your team will get a message as soon as someone books a trip.

Now that you know what a webhook does, you can set up your first one.

### Setting up your first webhook

What you'll need before you start: your external webhook URL ready to paste into WP Travel Engine.

<Steps>
  <Step title="Open Webhooks and API settings" title-type="p">

    This is where you manage webhook connections on your site.

    In the left sidebar of your WordPress dashboard, go to **WP Travel Engine**, then **Settings**, then **Webhooks & API**. You may also see it under **Bookings**, then **Settings**, then **Webhooks & API**.

  </Step>

  <Step title="Add a new webhook" title-type="p">

    This creates a new connection for the tool you want to send data to.

    Click **Add New Webhook**.

    <Image />

  </Step>

  <Step title="Fill in the webhook details" title-type="p">

    This tells WP Travel Engine where to send the data and which event should trigger it.

    Enter:

    - **Name:** "My First Webhook"
    - **Endpoint URL:** `https://your-app.com/webhook-receiver`
    - **Events:** Check "Enquiry Created"

  </Step>

  <Step title="Save the webhook" title-type="p">

    Saving the webhook turns the connection into something your site can use.

    Click **Add Webhook**. A secret key is generated automatically. Save that key because it is used later for signature verification.

    <Image />

  </Step>
</Steps>

Your webhook is now in place. The next step is to test it and make sure data is actually being sent.

### Testing your webhook with Pabbly

What you'll need before you start: a Pabbly workflow open and ready to receive data.

<Steps>
  <Step title="Open Pabbly Connect" title-type="p">

    Go to Pabbly and create a new workflow.

  </Step>

  <Step title="Add a webhook trigger" title-type="p">

    This tells Pabbly what kind of connection it should listen for.

  <Step title="Capture the webhook response" title-type="p">

  </Step>

  <Step title="Trigger the event in WordPress" title-type="p">

    This sends a real event from your site so Pabbly has something to capture.

    On your website, submit an enquiry form or trigger the event you selected when you created the webhook.

    <Image />

  </Step>

  <Step title="Check the response in Pabbly" title-type="p">

    This confirms the connection is working.

    If everything is set up correctly, Pabbly shows "Webhook Response Received" and displays the full JSON payload sent by your site.

    <Image />

  </Step>
</Steps>

If Pabbly receives the data, your webhook is working. It is also worth understanding how WP Travel Engine keeps those webhook deliveries safe and reliable.

### Webhook security and retries

#### Signature verification

Every webhook request includes this header:

```typescript
X-WTE-Signature: sha256=<hash>
```

This signature helps confirm that the webhook really came from your site and was not changed on the way.

<Callout kind="info" collapsed="false">

If you are working with a developer, ask them to verify the signature before trusting the webhook data. They should hash the raw POST body, compare it to the `X-WTE-Signature` header, and use a timing-safe comparison such as `hash_equals()`.

</Callout>

#### Retry logic

If the tool receiving your webhook is down or slow, WP Travel Engine tries again automatically.

| Attempt | Timing | Notification |
| ------- | ------ | ------------ |
| 1 | Immediate | - |
| 2 | 1 minute | - |
| 3 | 5 minutes | Warning email |
| 4 | 15 minutes | Warning email |
| 5 | 30 minutes | Critical email + auto-disable |

In plain terms, this means your site does not give up after one failed try. It keeps trying for a while, and if the problem continues, it warns you by email and can disable the webhook to prevent repeated failures.

That covers sending data out. The next part covers pulling data in when another tool needs it.

## Understanding the REST API

A REST API lets another app ask your site for information using a web address.

That can be useful if you want to show trip or booking information somewhere outside your website. For example, if you build a mobile app for your travelers, the app can use the API to show each customer their booking history.

To use the API, you first need to create API keys.

### Generating API keys

What you'll need before you start: permission to manage WP Travel Engine settings in your WordPress dashboard.

<Steps>
  <Step title="Open API Keys settings" title-type="p">

    This is where you create the login details another app will use to access your data.

    Go to **WP Travel Engine**, then **Settings**, then **Webhooks & API**, then **API Keys**.

    <Image />

  </Step>

  <Step title="Generate a key" title-type="p">

    This creates the API login details for your connection.

    Click **Generate API Key**. Choose the permissions you need. Then copy the Key and Secret.

  </Step>

  <Step title="Save the key" title-type="p">

    Saving makes the new key active.

    Click **Add API**.

    <Image />

  </Step>
</Steps>

Once your key is ready, you can test whether the API is working.

### Testing the API: the quick way

This method is useful for quick testing in Postman or for checking whether your key works.

It is less secure because your key and secret appear in the URL.

```bash
curl "https://yoursite.com/wp-json/wptravelengine/api/v1/bookings?accesstoken=wte...&accesssecret=wtesec..."
```

What you'll need before you start: your API Key and Secret copied somewhere you can paste from.

<Steps>
  <Step title="Create a GET request" title-type="p">

    This tells Postman you want to fetch information from your site.

    Open Postman, click **New**, then **HTTP Request**, and set the method to GET.

    <Image />

  </Step>

  <Step title="Enter the endpoint URL" title-type="p">

    This is the web address for the bookings list.

    Enter this URL without any parameters:

    ```typescript
    https://yoursite.com/wp-json/wptravelengine/api/v1/bookings
    ```

  </Step>

  <Step title="Add the credentials as params" title-type="p">

    This tells Postman how to prove it has permission to access your API.

    Go to the **Params** tab and add:

    | Key | Value |
    | --- | ----- |
    | Access-Token | YOUR_API_KEY |
    | Access-Secret | YOUR_API_SECRET |

  </Step>

  <Step title="Send and review" title-type="p">

    This checks whether the connection works and whether your site returns booking data.

    Click **Send** and review the JSON response.

    <Image />

  </Step>
</Steps>

<Callout kind="alert" collapsed="false">

This method is not secure for normal use. Your API key and secret appear in the URL. URLs can be saved in browser history and logged by servers, plugins, firewalls, analytics tools, CDNs, and reverse proxies. Use this method only for quick debugging, testing on non-production sites, or tools that do not support headers.

</Callout>

If the quick test works, use the more secure method below for anything long term or production-facing.

### Testing the API: the secure way

This is the recommended method.

Your credentials are sent in headers, so they do not appear in the URL.

```bash
curl -H "Access-Token: wteyourapikeyhere" \
     -H "Access-Secret: wtesecyoursecrethere" \
     "https://yoursite.com/wp-json/wptravelengine/api/v1/bookings"
```

Required headers:

```typescript
Access-Token: YOUR_API_KEY
Access-Secret: YOUR_API_SECRET
```

What you'll need before you start: your API Key and Secret ready to paste into the request headers.

<Steps>
  <Step title="Create a GET request" title-type="p">

    This starts a secure test request in Postman.

    Open Postman, click **New**, then **HTTP Request**, and set the method to GET.

  </Step>

  <Step title="Enter the endpoint URL" title-type="p">

    This is the same bookings endpoint used in the quick test.

    ```typescript
    https://yoursite.com/wp-json/wptravelengine/api/v1/bookings
    ```

    <Image />

  </Step>

  <Step title="Add the credentials as headers" title-type="p">

    This keeps your credentials out of the URL.

    Go to the **Headers** tab and add:

    | Key | Value |
    | --- | ----- |
    | Access-Token | YOUR_API_KEY |
    | Access-Secret | YOUR_API_SECRET |

  </Step>

  <Step title="Send and review" title-type="p">

    This confirms the secure setup is working.

    Click **Send**. The JSON response appears below.

    <Image />

  </Step>
</Steps>

<Callout kind="tip" collapsed="false">

Use the params method only for quick testing or checking whether your keys work. Use the headers method for anything secure, recommended, or production-facing.

</Callout>

## Real-world uses for your tour business

Here are some practical ways tour operators use webhooks and the API.

### Sync bookings with a CRM

If you use HubSpot, Zoho, or Salesforce, you can send new bookings into your CRM as soon as they happen.

Create a webhook, choose the `booking.created` event, and send the data to your CRM or to a tool like Zapier or Make that passes it on. That way, every new trek booking, family package enquiry, or private departure request reaches your sales team without manual copying.

### Send automated WhatsApp or SMS messages

You can notify customers the moment a payment goes through.

Create a webhook for `booking.payment.completed` and connect it to Twilio or your WhatsApp tool. This works well for sending payment confirmations, gear rental reminders, meeting point details, or itinerary updates.

### Sync with accounting or ERP software

If your finance team uses QuickBooks, Xero, or Odoo, you can push payment details into that system automatically.

Use the `booking.payment.completed` webhook event and map the payment amount to an invoice or accounting entry. This helps you keep cleaner records and spend less time matching payments by hand.

### Build a dashboard for sales and performance

If you want to track how your business is doing, the API can feed data into reporting tools.

Use the `/bookings`, `/payments`, and `/trips` endpoints with Power BI, Looker Studio, or Tableau. That can help you see revenue, best-selling tours, destination trends, and group booking performance in one place.

### Create a mobile app or customer portal

If you want travelers to log in and view their trips, the API makes that possible.

A developer can use the API to show booking history, trip details, and payment information in a mobile app or customer portal. That gives your customers the same information whether they check on their phone or your website.

### Connect partner platforms and affiliate systems

If you work with partner sites, channel managers, or affiliates, they may need trip and availability information from your site.

Use the `/trips` and `/bookings` endpoints to sync inventory and departure dates. This helps partners sell your tours with better accuracy and lowers the chance of overbookings.

## Tips if you're working with a developer

You do not need to handle the technical parts yourself. If a developer is helping you, pass these notes along.

<Callout kind="info" collapsed="false">

**For webhooks**

- Respond to the webhook quickly, ideally in under 5 seconds.
- Return HTTP 200 immediately, then process the data in the background.
- Implement idempotency so duplicate webhook deliveries do not create duplicate actions.

</Callout>

<Callout kind="info" collapsed="false">

**For the API**

- Use pagination with `perpage` to avoid large result sets.
- Cache responses on your side.
- Make large data pulls during off-peak hours.
- Use the `search` parameter to filter results on the server side.

</Callout>

If something does not work as expected, start with the checks below.

## Troubleshooting

### My API response is missing booking details

This usually means WP Travel Engine Cart 4.0+ is not installed or not active.

Go back to [What you'll need before you start](#what-youll-need-before-you-start) and confirm you are using WP Travel Engine 6.7.0+ and Cart 4.0+.

### My webhook isn't sending data

First, check that the webhook is active. Look for the green toggle in the webhook list.

Then make sure you selected the correct event, such as the enquiry event or booking event you want to track. Also confirm the main WP Travel Engine plugin is active on your site.

If the webhook still does not fire, check your WordPress debug log for errors.

<Callout kind="info" collapsed="false">

If you are working with a developer, ask them to confirm that the event is firing with WP-CLI by running:

```bash
wp eval "do_action('wptravelengine.booking.created', 123);"
```

</Callout>

### My webhook keeps getting rejected

This usually points to a signature mismatch.

Make sure you are using the webhook secret, not the API secret. Those are different keys.

<Callout kind="info" collapsed="false">

If a developer is helping you, ask them to check these points:

- Hash the raw POST body before JSON parsing
- Include the `sha256=` prefix in the comparison
- Use a timing-safe comparison such as `hash_equals()`

</Callout>

### I can't access the API and I keep getting an error

Start by checking that your API key and secret are correct. It helps to copy and paste them again carefully.

Then make sure the key is active and has the permission you need, such as `bookings.list`. For most real use, test with headers instead of query params.

If you want a quick health check, test with the `/test` endpoint first.

### The API stops working after too many requests

This usually means you hit the rate limit.

If you are pulling data into another tool, reduce how often that tool requests data. Caching responses can also help.

<Callout kind="info" collapsed="false">

If you are working with a developer, ask them to:

- Implement exponential backoff
- Cache API responses
- Check the `X-RateLimit-Reset` header to see when requests can resume

If you need a higher limit, contact support.

</Callout>

### My webhook got turned off automatically

This usually happens after repeated failed delivery attempts.

Check that your endpoint is online and reachable. Also make sure the endpoint returns HTTP 200 when it succeeds.

Review the webhook logs for the exact failure reason. After fixing the issue, re-enable the webhook in settings.

<Callout kind="info" collapsed="false">

If a developer is helping you, ask them to test the endpoint directly with:

```bash
curl -X POST https://your-endpoint.com/webhook -d '{"test":"data"}'
```

</Callout>

## Frequently asked questions

<ExpandableGroup>
  <Expandable title="Can I use webhooks and the API at the same time?" default-open="false">

Yes. They do different jobs. Webhooks push data out, and the API pulls data in when another tool asks for it.

  </Expandable>

  <Expandable title="Do webhooks send data right away?" default-open="false">

Yes. They usually send within 1-2 seconds after the event happens.

  </Expandable>

  <Expandable title="How many API keys can I create?" default-open="false">

As many as you need. It is a good idea to create separate keys for each integration.

  </Expandable>

  <Expandable title="Can I change what data the webhook sends?" default-open="false">

Yes, but this usually needs developer help. The filter hook is `add_filter('wptravelengine_webhook_payload', function($payload, $event) { ... }, 10, 2);`

  </Expandable>

  <Expandable title="What happens if the tool I'm sending data to is slow?" default-open="false">

The webhook times out after 30 seconds and then retries with exponential backoff.

  </Expandable>

  <Expandable title="Can I turn off the email alerts when a webhook fails?" default-open="false">

Not from the normal settings right now. A developer can filter email sending with `add_filter('wptravelengine_send_webhook_failure_email', '__return_false');`

  </Expandable>

  <Expandable title="How do I check if my webhooks are being sent?" default-open="false">

In your WordPress dashboard, go to **Settings**, then **Webhooks & API**, then **Logs**.

  </Expandable>

  <Expandable title="What versions do I need?" default-open="false">

You need WP Travel Engine 6.7.0+ and Cart 4.0+. See [What you'll need before you start](#what-youll-need-before-you-start).

  </Expandable>
</ExpandableGroup>
